# MizukiPanel 架构说明

本文说明 MizukiPanel 当前的模块边界、依赖方向和扩展约定，供后续功能开发与维护使用。

## 总体结构

MizukiPanel 是仅监听本机地址的 React 单页应用和 Hono API 服务。面板通过服务端访问用户选择的 Mizuki 项目；浏览器不直接读取文件系统，也不直接执行 Git 或 Astro 命令。

```text
浏览器（React + Material UI）
  └─ /api 请求
      └─ Hono 路由与安全中间件
          └─ 领域服务
              ├─ Mizuki 配置与内容文件
              ├─ Git 仓库
              └─ Astro 预览进程
```

## 客户端

客户端入口位于 `src/client/App.tsx`。入口只负责路由和页面懒加载，登录之外的页面统一经过 `RequireAuth`。

### 目录职责

- `pages/`：组合页面布局和功能组件，不承载文件格式或服务端业务规则。
- `layout/`：顶部栏、侧栏和页面外壳。
- `articles/`、`config/`、`features/`、`media/`、`preview/`、`publish/`、`workspace/`、`settings/`：按业务功能组织视图、状态 Hook、局部类型和常量。
- `components/`：可跨页面复用的展示组件。
- `hooks/`：跨功能使用的 React Hook。
- `shared/`：不属于某个业务功能的客户端工具和事件约定。
- `api.ts`：统一 HTTP 请求、响应解析和鉴权失败处理。
- `auth/`：鉴权入口、会话活动报告、退出状态机与未保存输入恢复注册；401 先保留本地内容再跳转，瞬时错误不丢弃输入。
- `types.ts`：客户端类型入口；跨端重复使用的项目、文章、配置、特色页描述和字体类型统一来自 `src/shared/`。

页面通过功能 Hook 读取和修改状态。组件接收明确的属性并负责渲染；网络请求集中在 Hook 或对应的功能模块内。客户端错误统一经 `shared/errors.ts` 转换为可显示文本。站点标题和头像变更通过 `shared/site-identity.ts` 中定义的事件通知界面刷新。

设置页由 `useSettingsController` 管理设置快照与草稿，`useSettingsLeave` 管理保存/放弃及离页保护，`SettingsSections` 组合懒加载表单。页面只组合导航、状态提示及对话框；切换分类和滚动时保留已访问表单。

配置与特色页共用 `CatalogLayout` 的搜索区域、网格与空状态，以及 `catalog-styles` 的卡片动效。领域模块保留各自的搜索字段、卡片动作和开关规则；文本查询的词项匹配由 `client/shared/search.ts` 统一处理。共享展示组件不读取领域 API。

### 导航与页面过渡

侧栏宽度先展开，单行文字随后淡入；快速反向切换会取消尚未开始的淡入。`layout/PageEntrance.tsx` 按路径和 `data-page-motion` 区域定义进入动画：工作区指标分批上移，文章列表逐项出现，配置/特色页按双栏顺序进入，媒体缩略图轻微缩放，预览控制与日志分区进入，发布步骤依次展开，设置先显示分类再显示表单，关于页采用较缓的居中缩放。

动画使用浏览器 Web Animations，异步区域在首次加载窗口内加入；用户开始交互后结束当前动画并停止接纳新的区域，轮询及查询参数变化不重播整页动画。只作用于首屏且限制区域数量，编辑器只淡入；不为动画重挂页面，完成后移除变换效果，保留固定定位、大纲、光标及撤销状态。页面级 Suspense 保留标题栏和侧栏。系统启用减少动画时，侧栏和页面直接切换。

## 服务端

服务端由三层组成：

1. `src/server/index.ts` 创建访问令牌并启动本机 HTTP 服务。
2. `src/server/app.ts` 组合安全中间件、领域路由、错误处理和静态资源。
3. `src/server/routes/` 将 HTTP 输入转换为领域服务调用，并返回 API 响应。

文件读写、格式解析、Git 操作、预览进程和发布流程位于 `src/lib/server/`。路由层不重复实现这些规则。新增 API 时，应先把可独立验证的业务逻辑放入对应领域模块，再由路由完成参数读取和响应映射。

`features.ts` 与 `publish.ts` 是领域的兼容导出入口，不承载业务实现。特色页的资源定义、开关目录、数据、正文、季度文件、相册、校验及存储分别位于 `features/`；发布的 Git 执行、运行状态、仓库概览、历史、提交、推送和构建分别位于 `publish/`。内部模块直接依赖所需模块，避免反向导入领域入口。

`workspace-history.ts` 独立读取和校验最近项目记录。设置存储通过它验证默认项目，不依赖负责连接和任务协调的 `WorkspaceSession`，从而避免设置、会话和任务服务之间的循环依赖。

### 安全边界

- 服务只监听 `127.0.0.1`。
- 访问令牌由启动进程生成并保存在内存中，仅用于登录校验。登录 Cookie 使用随机 HttpOnly、SameSite=Strict 会话 ID；领域模块 `panel-sessions.ts` 仅保存摘要和时间，Hono 实例绑定在 `server/session-manager.ts`。状态接口公开的 UUID 不能用于认证。
- 每个 API 请求由服务端校验会话期限和令牌轮换，活动报告不接受客户端时间；后台轮询不续期。写入先排队再异步鉴权，等待后再次核对期限和工作区版本，避免后到的切换抢先执行。
- 修改类请求经过来源校验和身份校验。
- 所有项目路径在服务端完成规范化和目录边界检查。
- 文章和配置写入使用版本值检测并发修改。
- Git 提交仅接收面板允许管理且由用户明确勾选的文件。

## 会话结束与恢复

`SessionGuard` 每 15 秒检查会话，页面恢复可见时检查；可见页面中的真实输入、点击、触摸和滚动最多每 30 秒报告一次。BroadcastChannel 通知其他标签页，不可用时继续轮询。`session-lifecycle.ts` 按登录代次忽略迟到的旧会话响应，重复 401 只启动一次恢复；服务端不通过过期响应清 Cookie，避免擦除新登录。

`session-recovery.ts` 先准备可编辑控件，再等待本地恢复副本落盘（上限 5 秒）。文章保留完整源码、独立 Frontmatter 和磁盘基准；设置、配置与特色页的未保存输入不自动提交服务器，失败时留在页面，允许下载恢复 JSON。过期后再报告活动不能恢复登录。手动退出只撤销本次会话；会话状态不持久化，重启服务要求重新登录，不会停止运行任务。实现、迁移及边界见 [阶段 8 说明](PANEL_SETTINGS_STAGE_8.md)。

## 状态与持久化

- 当前项目连接保存在被 Git 忽略的 `.local/workspace.json`。
- 面板个人偏好保存在浏览器，本机/项目偏好位于 `.local/settings.json` 与 `.local/project-settings/`；共享 schema 位于 `src/shared/panel-settings/`，不依赖 React 或服务端。设置实现与阶段边界见 [阶段 1 说明](PANEL_SETTINGS_STAGE_1.md)、[阶段 2 说明](PANEL_SETTINGS_STAGE_2.md) 和 [阶段 3 说明](PANEL_SETTINGS_STAGE_3.md)。编辑器显示偏好通过 CSS 和 Vditor 大纲/输入属性更新；默认模式仅在打开时读取。
- 文章恢复副本独立存于 IndexedDB，按实际项目/内容根目录、文章路径和编辑会话隔离，保留完整源码及独立 Frontmatter；恢复不写入磁盘。项目模板通过文章预览接口生成完整文件，创建时绑定实际内容目标、设置版本及内容摘要，再复用既有元数据/路径/URL 校验。
- 字体栈集中在 `src/client/font-families.ts`，文章字体由 `editorFontFamilies` 和 `useArticleFonts` 统一解析；全局等宽变量随界面字体同步，Vditor 通过 CSS 变量原位更新。排查范围与验证见 [字体同步检查](FONT_SYNC.md)。
- Mizuki 内容与配置仍以原项目文件为事实来源，面板不维护第二份业务数据库。
- 删除的文章和媒体先进入本地回收目录。
- 站点配置首次修改时通过 `/api/config/backup` 保留编辑前的完整文件，保存等待该备份完成；连续输入复用同一份。保存、放弃或撤销全部输入后再次修改会开启新的编辑批次。`config-backups.ts` 将备份按项目、内容根目录和配置名隔离，原子替换 `.local/config-backups/<归属摘要>.json`，每项只保留最近 5 份。配置页可选择恢复点，恢复前也备份当前状态；独立仓库的“尚无覆盖文件”可恢复为文件不存在。旧的通用备份仍由备份与维护管理，配置专用恢复点不参与其清理规则。
- Astro 预览状态和发布任务状态由服务端进程管理，客户端定时读取状态和日志。

## 依赖方向

依赖应保持以下方向：

```text
客户端页面 → 客户端功能模块 → API 客户端
服务端入口 → 路由 → 领域服务 → 文件系统 / Git / 子进程
```

领域服务不应导入 React、Material UI 或路由组件。客户端不应导入 `src/lib/server/`。共享模块只放入已经出现跨功能复用的代码，避免形成无边界的工具集合。

`tests/architecture.test.ts` 检查跨层依赖和特色页/发布服务可达依赖的运行时循环。字体等跨端类型也必须来自共享层，不能以 `import type` 绕过边界。

## 测试与验证

- `pnpm check`：TypeScript 静态检查。
- `pnpm format:check`：Prettier 格式检查。
- `pnpm test`：领域逻辑、服务组合和客户端纯逻辑测试。
- `pnpm build`：分别构建浏览器资源与服务端产物。

涉及布局、交互或主题的修改，还需在浏览器中检查桌面宽度、窄屏、浅色模式和深色模式。涉及真实项目的功能，应使用 Mizuki 项目完成连接、读取和受影响操作的冒烟验证。

## 扩展约定

新增功能时按以下顺序放置代码：

1. 在 `src/lib/server/` 中实现并测试业务规则。
2. 在 `src/server/routes/` 中注册 API。
3. 在 `src/client/<feature>/` 中实现状态 Hook 和功能组件。
4. 在 `src/client/pages/` 中组合页面，并在 `App.tsx` 注册路由。
5. 只在至少两个功能需要相同逻辑时，将其提取到 `shared/` 或通用组件目录。

每个文件保持单一职责。功能代码按业务领域命名，避免使用无法表达职责的通用文件名；提交信息遵循 Conventional Commits。
