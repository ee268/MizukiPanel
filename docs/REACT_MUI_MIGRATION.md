# React + Material UI 界面迁移

## 架构

- 浏览器端改为 React 19、React Router、Material UI 9、Material Icons 和 Emotion，由 Vite 构建。
- 本机服务改为 Hono Node API。现有路径守卫、事务写入、冲突检测、文章、媒体和 Astro 预览服务保持为独立服务层。
- 开发模式由启动器同时启动 Vite 与 Hono，`/api` 通过本机代理访问；生产模式由一个只监听 `127.0.0.1` 的 Hono 进程同时提供 API 和 `dist/` 静态文件。
- 页面按路由动态导入，避免把文章、媒体和预览界面全部放入首屏包。

## 页面布局

- 顶部标题栏显示当前模块和技术栈标识。
- 桌面端左侧固定导航，移动端使用同一导航的临时抽屉。
- 右侧内容区承载工作区、文章、站点配置、媒体和Mizuki预览；各页统一使用 MUI 的容器、卡片、列表、表单、弹窗、提示和响应式网格。
- 顶部调色板入口使用即时生效的下拉面板，采用与 Mizuki 相同的 0–360 色相模型，并支持浅色、深色和跟随系统模式。

## Frontmatter 编辑

- 每个字段显示为一行，左侧编辑字段名，右侧编辑 YAML 内容。
- 支持添加、删除和改名字段；字段名不能为空、不能重复，也不能包含 YAML 键分隔控制字符。
- 右侧内容作为单个 YAML 值解析，因此支持字符串、数字、布尔值、数组和对象。
- 保存前继续校验 Mizuki 已知字段、日期、URL 和文章路由，并使用文章版本哈希防止覆盖外部修改。
- 服务端用 `originalKey` 关联原 YAML 节点。字段改名时保留键前注释，修改值时保留值节点注释；正文保持原样。无法安全处理的文件仍可使用完整源码模式。

## 验证

- `pnpm check`：React、MUI、Hono 与服务层 TypeScript 检查通过。
- `pnpm test`：22 项测试通过，覆盖主题色、Frontmatter、站点配置 AST、本地恢复和独立仓库覆盖。
- `pnpm build`：React 客户端与 Hono 服务双构建通过，页面已经拆包。
- 生产服务真实验证：登录 Cookie、React 入口、工作区和文章 API 均返回 200；临时文章完成创建、字段改名、YAML 数组保存、正文保留和回收删除。
