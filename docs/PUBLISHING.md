# 发布管理

发布管理页管理连接的 **Mizuki 项目根目录**中的 Git 仓库，包括当前分支、远程仓库、过往提交、工作区修改与 Git 提交，并可独立运行 Mizuki 构建。独立内容模式下也使用 Mizuki 仓库，外部内容仓库不作为提交目标。

## 提交历史与仓库信息

进入页面显示当前分支的提交历史，每页 20 条，按 Git 历史顺序从新到旧显示。分页固定在读取时的 HEAD，避免新提交导致翻页重复或遗漏；刷新仓库后读取新的历史。点击条目查看完整提交说明和文件差异，超过 256 KiB 的差异显示截断提示。空仓库显示无提交记录。

右侧展示项目绝对路径、当前分支、HEAD、上游分支以及领先/落后数量，并列出所有远程仓库的读取与推送地址。远程跟踪状态来自本地 Git 记录；HTTP 地址中的凭据会被隐藏。可点击支持的 HTTP/SSH 仓库地址在浏览器查看。

## 选择性 Git 提交

“工作区修改”标签列出整个 Mizuki 仓库的新增、修改、删除、重命名与暂存状态。可逐项查看差异、勾选文件，并使用类型、作用域和说明组成 Conventional Commit。提交只包含勾选文件，不包含未选修改；提交成功后刷新状态和历史。项目设置中的类型、作用域默认值和记忆偏好继续生效。

只读项目、游离 HEAD、未解决冲突或已有暂存项会关闭提交入口。已有暂存项保持原样；提交失败仅撤销本次产生的暂存，不改动工作树文件。Git 操作使用参数数组和字面量路径，拒绝项目外路径。

## Mizuki 构建与运行日志

“构建 Mizuki”在项目目录运行 `pnpm run build`，可构建当前工作区中的未提交修改。是否能构建依据项目可写性及 `package.json` 的 build 脚本，Git 不可用也可独立构建。构建失败显示错误和进程退出码。提交与构建一次只执行一个任务，运行时阻止切换工作区。

仓库/分支/远程读取、历史分页、提交详情、文件差异、Git 提交以及构建均写入运行日志。构建的标准输出和错误输出持续追加，页面每秒更新运行中任务的日志。日志按项目隔离，默认保留最近 500 条，可在设置中调整数量、字号和自动滚动。记录保存在当前服务进程中，重启服务后清空。

页面已移除发布流程步骤、发布前检查、校验、独立内容同步、推送与还原模块，相应旧操作接口也已删除。
