# 设置阶段 5：媒体默认值与图片处理

完成日期：2026-10-10。设计依据：[设置页设计](PANEL_SETTINGS_DESIGN.md) §4.4、[阶段规划](PANEL_SETTINGS_STAGES.md)。本阶段实现项目 `media` 分组，不提前实现预览发布、维护或会话策略。

## 设置与默认行为

| 设置 | 默认值 | 行为 |
| --- | --- | --- |
| 上传范围、子目录 | 公共图片、空目录 | 下次打开媒体管理填入，可在表单临时修改；文章资源需选择所属文章 |
| 命名 | 保留原文件名 | 可选系统日期前缀或随机 UUID；任何模式都拒绝覆盖同名文件 |
| 图片引用 | 复制路径，插入 Markdown | 可指定 Markdown 或 HTML；图片选择框可临时调整插入语法 |
| 替代文字 | 文件名，不含扩展名 | 可改为空；上传和插入时可编辑 |
| 压缩、缩放 | 关闭 | 默认直接写入原始字节，不解码、不重新编码，不改元数据 |
| 压缩质量 | 85 | 50—100；JPEG/WebP/AVIF 使用质量参数，PNG 使用无损压缩 |
| 最大长边 | 1920 像素 | 64—8192；保持比例，不放大小图 |
| 输出格式 | 保持原格式 | 可选 PNG、JPEG、WebP、AVIF |

兼容扩展 schema 1，旧设置补齐默认值而不立即回写。表单复用分组保存、取消、恢复默认、离开提醒、版本冲突与损坏/未来版本保护；项目根目录决定设置归属。设置页保存不上传任何图片，也不修改已有资源。

媒体页面初次读取默认范围和目录，后续刷新列表不覆盖临时输入。“读取最新偏好”释放当前预览、保留文件和表单；“恢复上传默认值”重新填入范围、目录与替代文字。读取失败时仍可重试。

## 预览与上传

选择文件后点击“预览上传结果”，核对原图/处理后的体积、尺寸、目标文件和引用，再上传选定版本。预览只缓存内存，不写图片或临时文件到项目。处理失败保留原文件，不自动上传；用户需明确选择“上传原图”。动画与 SVG 不处理，并说明保留原样。

预览绑定真实项目与内容目录、资源范围、所属文章、目标路径和媒体设置；提交再次检查项目、只读状态、当前媒体设置、文章是否存在及文件冲突。无关设置更新不使已准备图片失效，媒体设置更新则要求重新预览。预览阶段发现重名会禁用对应版本；最终上传继续使用独占写入，处理并发重名。失败不消费有效预览，成功即释放。

| 限制 | 数值 |
| --- | --- |
| 单张输入与输出 | 20 MiB |
| HTTP 请求体 | 21 MiB，含 multipart 元数据 |
| 解码像素 | 3200 万 |
| Sharp 处理超时 | 8 秒 |
| 预览有效期 | 10 分钟 |
| 内存预览数量、字节 | 最多 8 份、80 MiB；优先释放旧预览 |

文件类型核对扩展名和文件头；路径继续复用真实目录、遍历、符号链接与受管理资源保护。公共资源写入实际公共图片目录，文章资源写入实际文章目录，支持本地和独立内容仓库。SVG 仅允许原文件上传，通过面板预览端点提供 sandbox CSP、禁止脚本和外部资源，并使用正确 MIME、`nosniff` 和不缓存响应；此策略作用于面板资源响应。

## 依赖、动画与透明度

使用锁定的 `sharp@0.35.5`，只在服务端启用处理时动态加载。Sharp 要求 Node.js 20.9 或更新版本，兼容项目既有 Node.js 20.19 要求；安装需要与目标平台匹配的原生依赖。若原生依赖不可用，处理返回明确错误，仍可选择原图。依据见 [Sharp 安装](https://sharp.pixelplumbing.com/install/)、[输入限制](https://sharp.pixelplumbing.com/api-constructor/)、[缩放](https://sharp.pixelplumbing.com/api-resize/)、[输出格式](https://sharp.pixelplumbing.com/api-output/)。

GIF、APNG、动画 AVIF、检测到多帧的 WebP/其他输入保持原样，SVG 不栅格化。透明图片输出 PNG/WebP/AVIF 时保留透明度，转换 JPEG 会拒绝处理并提示，避免静默铺底。处理会应用 EXIF 方向后再缩放，生成文件采用 Sharp 默认元数据策略；只有完全关闭处理时保证原文件字节和元数据不变。处理结果可能比原图更大，界面明确提示并允许选择原图。

## 引用与编辑器

引用编码中文、空格、百分号和 `#` 等文件名字符，预览先移除 URL 查询/片段再解码路径，避免把文件名中的编码 `#` 当片段。引用检查同时识别旧未编码路径与新编码路径，保留已引用资源的删除保护。

Markdown 替代文字转义方括号和反斜线，HTML 属性转义引号、尖括号和 `&`。图片选择框按项目偏好选择范围、替代文字与语法，插入到当前光标位置，继续使用 Vditor 原生编辑与撤销。补齐 Vditor Lute HTML 区块序列化：DOM 已解码的源码不再次解码，防止 `&quot;` 变为属性分隔引号；运行时补丁匹配失败会明确报错，升级依赖需复核。
