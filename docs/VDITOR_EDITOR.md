# Vditor 文章编辑器

文章的“文档编辑”默认接入官方 [Vditor](https://github.com/Vanessa219/vditor) 4.0.0。通过 `pnpm` 拉取发行包并锁定版本，不修改上游源码；React 封装位于 `src/client/articles/VditorBodyEditor.tsx`。原来的 Milkdown 编辑器保留为备用，入口移至文章右上角“更多 → 使用备用编辑器”，选用时才加载其代码。备用界面可通过“返回 Vditor”切回。

## 使用与保存

- Markdown 与内置教程默认使用即时渲染模式；Vditor 工具栏可切换所见即所得和分屏预览。
- MDX 文章默认使用分屏源码模式，以保留 import、JSX 和表达式。组件不会在面板中执行；Mizuki 自定义指令和 MDX 的最终效果仍通过真实预览核对。需要已有的扩展卡片编辑能力时，可选择备用编辑器。
- Frontmatter 继续使用独立表单；Vditor 仅编辑正文。`vditor-source.ts` 保留原始 Frontmatter 切片、BOM、注释和 LF/CRLF 换行约定。
- 打开、查看和无修改切换不会将 Vditor 初始化时的格式规范化结果写回草稿；撤销回初始正文时恢复初始原文。实际编辑会使用 Vditor 的 CommonMark/GFM 序列化，因此正文空白、标记写法可能被规范化。
- 保存按钮和 Ctrl+S 在调用现有保存流程之前同步读取当前编辑内容，避免输入回调的延迟造成漏存。切换完整源码、Frontmatter 或备用编辑器之前也会读取当前内容。切换编辑器共享草稿，各编辑器的撤销栈在当前实例内生效。
- 保存继续使用现有正文接口及片段校验；图片删除或语法结构改变无法满足片段校验时，沿用完整源码保存流程。版本冲突、只读模式和未保存 Frontmatter 的处理不变。

## 图片、样式与历史

图片工具接入现有媒体库和 URL/项目路径输入。Markdown 保存 `/images/...` 或文章相对路径，显示时通过 CSS 图片替换加载受限媒体 API，不把面板 API 地址写入正文。图片对话框保留插入位置，图片标签和含空格、括号的路径通过适配函数转义。

封装使用 Vditor 原生输入、撤销和重做，不在单次图片删除时重建正文编辑器。对即时渲染/所见即所得模式的选区删除，调用 Vditor 公开的 `deleteValue()`，避免上游首次按键记录光标时使 HTML 源码选区折叠。主题切换调用 `setTheme()`，保持正文和历史；只读和保存中调用 `disabled()`，自定义图片按钮同步禁用。

编辑区域适配面板深浅色主题以及系统/自定义字体；正文和代码字体分开。可视化/完整源码切换的滚动锚点支持 Vditor 的渲染块，无法匹配时保留原有比例定位。

## 本地资源

`scripts/vditor-assets.ts` 为开发服务器提供 `/assets/vditor/` 资源，并在 Vite 生产构建时将发行包的 `dist/js`、`dist/css`、`dist/images` 和 MIT 许可证复制为同路径构建资产。Lute、中文语言包、图标、语法高亮、数学和图表依赖按 Vditor 的请求路径从面板同源加载，不依赖公共 CDN。升级依赖后重新构建即可同步资源。

`vditor-runtime.ts` 先完成语言包和 Lute 加载，再创建实例；错误显示在编辑区域内，支持 React StrictMode 与快速切换页面时的清理。网络图片和上游图表中使用远程服务的类型仍依赖各自地址。

## 验证

正文适配测试覆盖 Frontmatter/BOM/CRLF、MDX 原文和图片转义。隔离浏览器检查覆盖深浅色主题、三种编辑模式、正文及 Markdown/HTML 图片删除的撤销重做、立即保存、媒体库入口、新旧编辑器切换、只读/保存状态与本地资源加载。运行 `pnpm check`、`pnpm test` 与 `pnpm build` 检查类型、回归和生产资源。
